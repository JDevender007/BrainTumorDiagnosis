SECTION 1: PROJECT OVERVIEW
================================================================================

Project Name: BrainTumorDiagnosis
Purpose: Multi-task deep learning framework for brain tumor classification,
         segmentation, and uncertainty estimation from MRI images.
Approach: Tumor-Aware Multi-Task Network (TumorAwareMultiTaskNet) that jointly
          learns classification, segmentation, and uncertainty in a single pass.
Languages: Python 3.13.14
Framework: PyTorch 2.11.0+cu128, torchvision 0.26.0
Total .py files: 95
Total lines of code: ~15,000+
Tests: 73/73 passing

Key Innovation: A multi-task architecture that uses attention-weighted pooling
to focus on tumor regions, a lightweight 2D segmentation decoder for auxiliary
supervision, and MC Dropout uncertainty heads — all sharing a single backbone.
The model achieves 96.4% accuracy on the internal test set and 99.2% on the
external Kaggle dataset while being compact (9M params, 34 MB) and fast
(48 ms latency, ~21 FPS on RTX 3050 Laptop).

SECTION 12: PROPOSED MODEL — TumorAwareMultiTaskNet ARCHITECTURE
================================================================================

File: models/tumor_aware.py (410 lines)

Class hierarchy:
  TumorAwareConfig (dataclass)
    - backbone: str = "densenet121"
    - pretrained: bool = True
    - num_classes: int = 4
    - segmentation_classes: int = 5
    - dropout: float = 0.3
    - fusion_dim: int = 256
    - use_attention: bool = True
    - use_segmentation: bool = True
    - use_uncertainty: bool = True

  TumorAwareMultiTaskNet(nn.Module)
    ├── Backbone (DenseNet121 by default)
    │   └── Output: feature map (1024-d for DenseNet121)
    ├── SpatialAttention
    │   └── Conv2d(1, 1, kernel_size=7, padding=3) → Sigmoid
    ├── ChannelAttention
    │   └── AdaptiveAvgPool2d(1) → Linear → ReLU → Linear → Sigmoid
    ├── TumorRegionPool
    │   └── Applies channel+spatial attention → weighted pooling
    ├── AttentionFusion
    │   └── Learnable fusion of global features + tumor-region features
    ├── ClassificationHead
    │   └── Linear(1024, fusion_dim) → ReLU → Dropout → Linear(fusion_dim, num_classes)
    ├── SegmentationHead (lightweight 2D decoder)
    │   └── ConvTranspose2d chain for 2D segmentation masks
    └── UncertaintyHead
        └── MC Dropout layers for uncertainty estimation

Forward pass:
  1. Backbone extracts features from input image
  2. TumorRegionPool applies attention to focus on tumor regions
  3. AttentionFusion combines global + tumor-region features
  4. ClassificationHead produces class logits
  5. SegmentationHead produces 2D segmentation mask (auxiliary task)
  6. UncertaintyHead estimates prediction uncertainty via MC Dropout

Key design choices:
  - DenseNet121 backbone: good accuracy/speed tradeoff, 8M params
  - 2D segmentation head (not 3D): lighter weight, compatible with 2D images
  - Attention-weighted pooling: forces model to focus on tumor regions
  - Learnable fusion: model learns optimal combination of global/local features
  - MC Dropout: provides uncertainty without ensemble overhead

Total parameters: 9,034,416
Model size: 34.46 MB
Latency: 48.63 ms (single image, RTX 3050)
FPS: 20.6

    decoder1: Conv3d(32→16) → BN → ReLU → Conv3d(16→16) → BN → ReLU

  Output: Conv3d(16→5) → 5-class segmentation

Skip connections: Between encoder and decoder at each level

SECTION 21: MIXED PRECISION AND GRADIENT HANDLING
================================================================================

Mixed Precision (AMP):
  - torch.cuda.amp.autocast() for forward pass
  - torch.cuda.amp.GradScaler() for backward pass
  - Enabled in all training configurations
  - Mandatory for 4GB VRAM constraint
  - Reduces memory usage by ~40%

Gradient Accumulation:
  - grad_accumulation_steps: 1 (default, configurable)
  - Effective batch size = batch_size * grad_accumulation_steps
  - Used when batch_size=16 is too large for VRAM

Gradient Clipping:
  - torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
  - Applied after every backward pass
  - Prevents gradient explosions

Memory optimization:
  - pin_memory: false (Windows compatibility)
  - num_workers: 0 (avoids multiprocessing issues on Windows)
  - Small batch sizes (4-16)
  - Mixed precision reduces memory by ~40%
